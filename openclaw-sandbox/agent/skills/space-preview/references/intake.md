# 归站与路线理解

首看是交付顺序，不是任务目标的降级。用途保留原话；编排和补图沿用首看项目、父版、站点 ID。没有独立通路依据先给看景草稿，原导览目标仍待完成，不把推荐顺序当通路。

正常分支：用户说「从入口经活动区到办公室再沿原路回来」，附件按三个站分组，保留原片组，建立入口、活动区、办公室三个稳定 ID；用户的站序是参观意图。原路返回仍是同三站的反向边，不复制站点。

按宿主的收件命令处理直传照片和 ZIP。逐件核对回执的文件名及 `status`，有缺件时保留已到原件和 `purpose`，只请重发缺件。看景请求可以先发首看链接。明确要求首轮完整导览时，用 `first_look.continuation` 提供的工程、确切父版和清单在同一轮继续。根据联系表的固定地标、机位和重叠编排，上传顺序只作编号。同站选辨认地标最清楚的球面，其余放入 `alternates`；无法区分的列出具体照片候选。清单示例：

```json
{"title":"实景导览","entry":"entry","route_evidence":"用户确认参观顺序","stations":[
  {"id":"entry","name":"入口","files":["入口/IMG_01.jpg","入口/IMG_02.jpg"],"links":[{"to_id":"hall","cut":true}]},
  {"id":"hall","name":"大厅","files":["大厅/IMG_10.jpg"],"links":[{"to_id":"entry","cut":true}]}
]}
```

普通照片每站 1–24 张；每张 32 MB、每站 35 MB，常规导览最多 32 站。已确认完整的 2:1 等距柱状球面图每站一张，加 `spherical:true`。有拍摄记录时同站 `capture` 指向记录 JSON，照片对应记录原名。未分组先看固定地标、重叠和文件信息；候选说明文件、站点、依据及无法判明项，实质冲突时集中问一次。不同站位分开，不能为了补全覆盖拼在一起。

按相机方向校正后的尺寸和实拍内容确认球面，2:1 宽高比可作筛查。JPEG 或 MPO 优先读取主帧。聊天若在收件前提示单图像素超限，定位受影响的一件，保留原图，按可用渠道提交原图 ZIP，或经说明后只提供该件兼容副本。模型只需查看联系表和透视局部，已收的原图继续参与实际处理。

拼接后用站点回执 `used_files`、`unused_files`、`view` 和 `geometry` 检查参与的原片与实际覆盖。弱匹配保留原照或局部；水平闭合的圆柱全景按实际垂直角度说明，只有真实经纬覆盖完整的球面才称 360×180°。在实景中检查重影、接缝及通路附近的地标，保存可用范围。

同批平面图请在文件名标「地图」「平面图」或 `map`。收件结果的 `photos[].kind:"map"` 保留图件供编排，但不当作全景站点，也不挡住整球首看；仍需看图核对内容及点位。地图配置见 [地图与多点位](navigation-map.md)。

单张损坏时 `photos[].kind:"invalid"` 带具体 `error`，仅此件排除编排；原件仍在任务，合格图继续，不能要求整批重传。解码失败的占位图只能说明错误，不能说看到了损坏原图。需要换现有站的画面，写 `next_action:{kind:"photo",station_id:"原站ID",title:"具体问题",note:"原因、补哪个位置、怎样拍"}`；Web 会显示该站真实原图缩略图并绑定替换。保存父版可恢复；像素改变后仅本站失效方向重新确认，其他站继续保留。

线性认路清单在实际终点已识别时加 `destination:"终点站ID"`。它只指定目的地和停留点，不产生通路，也不要求移除排在后面的待归站照片。固定路线和场馆继续用各自清单结构。

开场构图以访客能认地标、看清朝哪走为准。编排沿用首看中未替换的整球时，可在站点的 `opening` 填 `yaw`、`pitch` 及可选的水平视角 `hfov`（度；默认 70，最多 90，越大看得越宽）。按球面联系表的地标位置设置；仅认出地标但没核过开场时，只说画面里能找，别说打开就能看见。变更球面后重新核开场和相关方向，开场不作为通路证据。
