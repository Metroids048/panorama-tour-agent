# 从现有照片开始

先判断用户当前状态，先给能立刻做的一件事，再按需展开。技术规格、全路线清单和分享托管不应同时挤进新手首答。

## 还没拍：先试入口这一站

首答先给这一步，三到四条足够，不先列七八个机位：
1. 站在能同时看到入口标牌、脚下路和通道的位置，拍完这一站再移动。
2. 手机横拿，用正常主摄或常见广角，站定保持高度，转身拍一圈。相邻约三分之一重叠，末张接回首张；通常十几张但取决于视野，不能用张数保证完整。
3. 放大看门牌是否清楚、通道有无遮挡、画面是否模糊，先把这一站原图发来试效果。
4. 一站试好，再规划转弯、岔路、终点与回头方向。用户明确索取完整清单时可直接给短表。

手机系统的长条“全景”通常不是完整360°球面。已有长条也可以先看实际范围，不让用户先买设备或重拍所有照片。不能承诺任意环拍都能无缝拼接；实际结果看重叠、视差与纹理。

## 已拍一部分：先看本人实景，只补缺口

有附件先走现有收件和本人首看主链；未附图就请发已有照片，同一机位一组。不要先发完整拍摄教程。保留清楚可用的照片和已确认方向，区分已拍到的水平/垂直范围与完整球面；不足时原照仍可看。补图建议必须具体到“缺哪一站或方向、站在哪里、朝哪里、需看到哪个固定地标和通道”。楼梯缺另一端只补对应端；去程可见但来路缺失不能称可往返。不能把建议机位当作已核实的实地通路。

## 已有完整球面：按站上传，继续编排

每站一张原尺寸2:1球面图，按真实地点命名，补楼层、日期与已知去回关系；有位置图可附，无图可先制作。不要再次要求普通环拍。

## 按需展开的完整清单

完整全景为主体验：每站一张完整的 2:1 等距柱状球面图，建议 6000×3000 或以上，原尺寸 JPG，单张不超过 32 MB、100 MP（1 亿像素）；常规导览每份最多 32 站。相机保持稳定、机位高度接近，擦净镜头，离开前检查前后左右、头顶和地面、接缝重影、曝光与标牌清晰度。普通长条、聊天截图和放大低清图不等于完整高清球面。

数量取决于空间覆盖：覆盖入口、各分支、转弯前后、遮挡后的过渡、主要看点与目的地；相邻站要分别认得出去向和来路。资料齐全时直接继续编排，不把缺图说明作为主流程。附件总量超过单轮 48 MiB 时按同一任务分批上传，保留原文件名和全部站点，不擅自截掉第 9 站以后的素材。

地图为可选输入：可提供有权使用的楼层图、校园图或手绘简图，标注与全景文件名一致的站点编号、入口、分区和物理楼层。让用户确认点的位置及通道；照片本身和文件顺序不能确定地理坐标。无图仍可制作，访客看到的是基于已确认实景连接的非比例通道示意。

目标是让第一次来的访客认得出、走得通、回得来。不要按文件数量安排站点，也不要用不连续的散图凑路线。先问用途并复用已经知道的起点、终点、访客和方向要求；有足够信息就直接给清单。无法确定的机位标成待现场选点，不能把建议位置当作已拍到或确认通行。

工作台[拍摄与上传指南](http://127.0.0.1:18792/#capture-guide)可以选择固定路线、场馆或校园，填写起终点，下载检查清单。用户需要完整规划时，聊天里的计划应更具体，采用“机位 → 要拍清什么 → 下一站与回头方向”的短表，标记必拍的入口、转弯、岔路、遮挡后新视野和终点。

- 固定路线：先实际走一遍；转弯前后各设可辨机位，终点拍清正确入口。去程与回程分别确认；直路看不见下一站就加过渡，不靠固定距离机械设站。
- 场馆：先列真实楼层，再列区域、目的地和访客可自由选择的分支。楼梯/电梯入口、出口及两端层号都拍，标明从哪层到哪层。没有两端和连接依据时只能分层浏览，不可承诺跨层沿箭头走。
- 校园：优先覆盖容易混淆的校门、岔路和目的地；校名、路牌、楼名和脚下道路尽量同框。跨广场或转入小路后补一个能回头认来路的站点。

每站是一处固定机位。普通照片使用正常主摄或常见广角，横拍、保持高度、站定转身，尽量锁定曝光；相邻约三分之一重叠，整圈首尾也重叠。先检查模糊、歪斜、过暗、逆光和标牌是否可辨。不要边走边拍后当成同站拼接，不把裁切全景、AI 外扩当作新原片。完整球面每站一张，保留原文件。实时手机采集引导尚未实现。

每站一个文件夹，如 `01_北门内侧/`、`02_路口转弯前/`、`03_转弯后/`、`04_目的地/`。附一段路线说明，写站名、物理楼层、固定地标、拍摄日期、允许交付范围和去回关系，如 `01 ↔ 02 ↔ 03 ↔ 04`，说明每个方向的门洞或通道依据。文件名与文字是用户描述，仍须结合原图判断，不能自动当作路线事实。

上传原图或 ZIP 后，继续既有逐件收件、本人首看、原项目编排和同版交付。已有不完整输入时先保留可用画面与方向，再明确缺哪一站、在哪拍、向哪拍、需看到什么；只要求补对应内容，不能重新拍一遍代替具体诊断。
