# 画面与门位复核

14K 原图被读图工具省略或联系表不足以认清门洞时，使用当前运行目录的 `inspect_spheres.py <当前球面原图> <任务内检查目录>`，读取回执中的透视局部图。能从联系表定位候选方向时，直接用 `--view YAW PITCH`。在 960×672 的 `anchor.jpg` 上选通路内部有余量的实际可走像素，避开草地、围栏、门框和台阶边缘。坐标从整张图左上角计起，包含顶部 32 像素标题。用同一视角加 `--point X Y`，从该次回执取得 `anchor_yaw`、`anchor_pitch` 与居中图 `centered_preview`。先核对圈心所在实物和对端通路，再把坐标写入清单。目录输入仍输出联系表。分析视图保留原件和交付画质。

核对来源原片和导览截图的左、中、右；整圈另看首尾，检查门框、墙线、黑区及近景重影。模型建议可以写 `suggestions:[{"to_id":"office","evidence":"2.jpg 右侧门框与办公室来向同一玻璃隔断","pending":"确认走道连到办公室"}]`。候选不渲染。目视报告站、原片、地标、疑点及动作（保留、缩到可靠范围、改看原照）。

同机位有多档时，优先核对并使用许可范围内能取得的最清楚实拍球面或图块。换高清图后重看开场、去回箭头和地标。查看器按设备支持回退，以实际清晰度核对标牌、入口和岔路。「查看原图」打开同站图像。符合条件的 JPEG 或 MPO 的球面另存保留主画面像素，MPO 只提取主帧。超出导出范围或需要方向校正时按实际结果说明。图块重投影球面注明来源，普通照片在 HTML 内为预览。用户需要字节一致的上传件时从同版原件归档取用。

开场先让访客认出当前位置。沿途提示写清「认什么、往哪走、到哪里停」，到达后给已有依据的回程提示。转开后应能找回箭头；去回分别看对应地标。缺过渡机位、入口开放条件未知或只能切换浏览时，在该段明示。

已确认真实站点关系且锚点在源站当前实景可见时，工作台点击，或在清单加入 `{"to_id":"office","yaw":-0.19,"pitch":-10.22,"view_revision":"源站回执值","confirmed_by":"确认者","evidence":"活动区桌列后的开口，馆方原导览及实景交叉核对"}`。球面或局部角度单位为度；原照坐标用 `photo`（零基序号）和 `x,y`（0–1）。每个方向独立。用已验证坐标或工作台点击，禁止从屏幕位置猜角度。

走向地标和沿哪条通道分别确认。街道箭头贴在实际人行道或已确认的过街入口，室内贴在门洞净空或可通过的踏步内。去程与回程各看一次落点图或保存版实景。图上能切站、路线大体朝对、对端建筑可见都不足以证明能沿箭头走。

从源站找实际可穿过的开口或通道，用目的站来向、连续过门照片、实测轨迹或用户确认交叉核对。逐方向核对箭头中心及附近可通行区域：门洞内的净空、道路铺装、楼梯踏步；中心避开门扇、车辆、扶手、立柱、石块和草地。横杆与栏杆要辨认实际绕行空隙，楼梯要分清踏步与平台；提示说的走法与箭头所在通路一致。远处方向正确但中心压在障碍上仍须返修。中间站的去、回箭头各贴自己的实景方向，允许要转头才看到另一支。

楼梯、栏杆及狭窄门洞不能只凭联系表判断：放大实际保存版的箭头截图，并转到相邻角度核净空，特别检查扶手末端与第一阶踏步。换用邻近清晰原片时，以该片真实拍摄点更新来源和位置，重新核对该站开场、两侧去回通道及两端的原片绑定；不能沿用旧片确认状态。

## 通用成品输出标准

以下用于新制作、局部美化及补取后的最终效果复核，覆盖本任务每一站、每个已确认方向，不限当前案例：

1. **认得位置。** 首屏和首次到站能辨认所写地标及通道；短提示交代认什么、往哪走、到哪里停。按任务约定的实际桌面窗口核对牌匾、箭头与操作控件可见，地图与地点目录默认收起，实景占主画面。正式场馆打开即进入入口全景，总览仍可返回选房间或楼层；少图首看草稿保持范围说明和总览，不冒充正式实景导览。首次操作提示与走法共用一块自适应区域；长名称、分支和首次提示同时出现时仍不重叠、不裁切。长路线提示按需展开在同一导航卡的操作行下方，不能用固定偏移覆盖换行后的控件；地标与原提示保留可读入口。展开提示或改选目的地时，所选实景箭头若被提示卡遮住或在视野外，应转向真实通道使其可见可点，不改写通道坐标；看提示不等于切站。顶部长标题须在自身容器内省略或换行，不得撑宽页面；顶部换行时，实景按剩余高度伸缩，不能裁掉底部提示或历史范围。
2. **看得清楚。** 在同一站同视角比较原片、保存预览及实际下载件，核原图尺寸和浏览器实际纹理上限；源图已有模糊按实说明。检查「查看原图」确属同站；文件存在或像素数大不能代替看清标牌与入口。
3. **走得正确。** 每个去、回方向均按上文检查实际落点，并在实际离线网页点击到正确站、到达终点及沿箭头返回入口。拖动时箭头随对应地标移动、转开后离开画面、再转回来可点到。固定控件和地图跳点分别记作选景；楼层覆盖按实际楼层及可走楼梯判断。
4. **信息一致。** 地图、目录、当前位置与箭头目标指向同一站；地图不显示内部数字，密集位置可按名称展开；地图与底图规则见 [地图与多点位导览](navigation-map.md)。地图双指及滚轮缩放保持所指地点，拖动、手势取消后仍能正常选点和定位，不能把张合手势当成地点点击。名称描述可辨外观，明确实际覆盖、拍摄日期、许可及历史开放限制。
5. **切换连贯。** 切站保留旧画面直到新画面就绪，再短暂过渡；保留清晰原图与失败重试。只保留当前、上一站和一个相邻预备场景，返回复用上一站实际渲染结果，避免重复上传纹理；离开、失败恢复及销毁时清理失效场景，取消上一站尚未执行的预载，防止当前目标被重复建立。回初始视角复用当前场景，只恢复方向与缩放。正常、悬停与键盘焦点状态均须保持方向符号清楚可辨，主题覆盖须成对检查前景和背景颜色；缓存画面内的箭头也须完全隐藏且不能取得焦点；连续往返后核对画面，不能只检查当前站 DOM 中的箭头数。按同输入、同设备测去程、立即返回、连续往返与地图远点；同时测连续快速经过未预载分支的冷切站、首次打开及真实拖看；拖看记录浏览器帧回调间隔与长停顿，并与画面观察结合，不把回调间隔冒充真机帧率。记录点击至画面就绪的时间及实际清晰度，不把小图回归或预备方向的速度推广到所有方向和设备，不以降画质制造加速，不预先解码全场所有高清球面。按钮文案说明实际动作，分支不按数组强行解释前后站。
6. **交付同版。** 保存预览、聊天下载、历史补取须绑定同一项目和确切版本；开发验收只复制该 HTML 到空目录并改名、断网检查上述行为。每次返修对照父版，保留原图、ID、站序、未受影响方向和原目标；换图或改方向后重验受影响落点及其去回通路。

严格保存／取件程序检查结构、全景和覆盖；上述实景位置、可读性与视觉遮挡由实际画面复核，程序通过不代表已完成视觉审查。开发者必须实际查看同版首屏、首次提示、目录、小地图、展开地图与每一楼层截图，至少覆盖 1440×900、1280×720、820×900 及窄屏；看见问题先修再重看，不能关闭提示后截一张截图当作全部状态通过。业务 Agent 用现有读图和任务入口核图并如实报告；浏览器离线及全方向点击由开发验收执行。证据记录项目、版本、实际文件与范围，分别标程序检查、模型视觉检查、原生续做、真人及用户接受；未做项保持待验。

缺过渡分支：如果回执给局部或原照，保留真实覆盖及有证据的方向；通道拍不到则保留待确认或直接切换。举例：站回活动区原地，朝办公室开口补一张，同时带上左侧桌端和玻璃门框。若无法在实际画面定位，不写坐标；360° 只用于实拍闭合或确认的完整球面。
